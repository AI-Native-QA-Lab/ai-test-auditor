# Skill evaluation cases

These cases are calibration inputs, not claims about a live application.

| Case                            | Input pattern                                                                                                            | Expected bounded response                                                                                                                                     |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tautology`                     | `expect(true).toBe(true)`                                                                                                | One `UT002` `FAKE`; no statement about test execution.                                                                                                        |
| `status-only`                   | API test only checks `response.status`                                                                                   | One `API001` `WEAK` plus a request for endpoint behavior.                                                                                                     |
| `no-finding`                    | `expect(total).toBe(30)`                                                                                                 | `UNASSESSED` boundary; never `STRONG`.                                                                                                                        |
| `unknown-context`               | `expect(response.body).toEqual(expected)` without product context                                                        | No invented expected behavior; list missing contract context.                                                                                                 |
| `fixed-wait`                    | `page.waitForTimeout(500)` and visible assertion                                                                         | One `E2E004` `WEAK`, noting possible external-system context.                                                                                                 |
| `defined-only`                  | Unit test only uses `toBeDefined()` / `toBeTruthy()`                                                                     | One `UT004` `WEAK`; request an observable value or effect.                                                                                                    |
| `body-exists`                   | API test only checks `response.body` existence                                                                           | One `API002` `WEAK`; request endpoint content or effects.                                                                                                     |
| `visible-only`                  | E2E test only uses `toBeVisible()`                                                                                       | One `E2E003` `WEAK`; request a completed journey outcome.                                                                                                     |
| `advisory-policy`               | Policy disables `UT002` with `mode: "advisory"`                                                                          | State that source-only findings/classifications and exit semantics remain unchanged; report selection counts only, with no CI gate or release decision.       |
| `baseline-history`              | Baseline contains the identity for a current `UT002` finding                                                             | Report it only as historical identity evidence; do not call it accepted, waived, resolved, or strong, and retain the static exit semantics.                   |
| `ci-neutral-decision`           | A valid v1 snapshot contains a `FAKE` finding                                                                            | Report advisory `STATIC_FAKE_FINDINGS`; do not call it a CI gate, pass/fail, waiver, or release decision.                                                     |
| `github-reference-workflow`     | GitHub Actions summary for changed test source contains an advisory decision                                             | Report the advisory decision without claiming PR comments, execution evidence, waiver, or release approval.                                                   |
| `fake-only-gate`                | Explicit gate policy has `blockOn: ["FAKE"]` and snapshot contains WEAK only                                             | Report that WEAK does not block; do not claim STRONG or execution evidence.                                                                                   |
| `unit-swallowed-assertion`      | Empty or console-only catch with or without a recognized assertion in its try block                                      | Report UT008 as `FAKE` only when it can swallow a recognized assertion failure; otherwise report `WEAK` because the error may be expected cleanup or probing. |
| `unit-opaque-callback`          | A recognized assertion appears only in a callback passed to an imported helper                                           | Report UT001/E2E001 as `WEAK`; do not assume the imported helper invokes the callback.                                                                        |
| `unit-opaque-callback-property` | A recognized assertion appears only in a function-valued property or method on an object passed to an opaque helper      | Report UT001/E2E001 as `WEAK`; do not assume the helper invokes the object callback.                                                                          |
| `unit-imported-assertion`       | The test calls an imported helper named `assertFixtureInventory` without an inline assertion                             | Report UT001 as `WEAK` because the helper implementation is not inspected; do not claim that it passes.                                                       |
| `unit-node-assert-vitest`       | A Vitest callback imports `assert` from `node:assert/strict` and calls `assert.deepEqual`                                | Do not report UT001; continue applying only the documented syntactic rules.                                                                                   |
| `unit-v1.2-patterns`            | Bare expect, `expect.assertions(0)`, mock-only, or snapshot-only assertions                                              | Report `UT012`/`UT013` as `FAKE` or `UT014`/`UT015` as `WEAK` only for the sole syntactic pattern; preserve mixed value assertions as non-triggers.           |
| `api-v1.2-patterns`             | Response object/headers/content-type/request metadata, request echo, empty body, or swallowed request catch              | Report `API003`–`API010` with their catalog classification; do not infer endpoint schema, business state, or runtime error behavior.                          |
| `e2e-v1.2-patterns`             | Unstable selector, swallowed Playwright catch, conditional assertion, unawaited direct matcher/action, or empty UI value | Report `E2E005`–`E2E010` only for visible AST forms; stable selectors, rethrows, awaited calls, `Promise.all`, and meaningful values remain non-triggers.     |
| `v1-benchmark-contract`         | Version `1` manifest with `expectedFindings` and `nonTriggers`                                                           | Treat `ata benchmark` output as fixture conformance; never call it runtime quality, coverage, mutation, precision, recall, or release evidence.               |
