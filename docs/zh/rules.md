# 规则目录

目录共包含 31 个稳定 rule ID：10 个 Unit、10 个 API、10 个 E2E，以及 1 个 parser 规则。

## 如何理解发现项

发现项均是局部语法证据，置信度与具体模式相匹配。信息说明观察到的模式，不证明整个测试或应用必然有缺陷；修复建议应作为人工审查的起点。

## 误报控制

- 规则只检查提取出的测试回调和有边界、静态可达的代码，不读取执行结果。
- `API001` 和 `E2E002` 要求有限断言是所有已识别断言的唯一目标。
- `E2E004` 只命中数值字面量；变量不命中。
- `UT004`、`API002`、`E2E003` 要求每个已识别断言都符合狭窄的存在性/可见性模式。`.not`、裸 expect 和混合断言会抑制提示；`.resolves`、`.rejects` 和可静态解开的 `expect.poll` 保留原 matcher 含义。
- Node `node:test` 的断言识别要求存在从 `node:assert` 或 `node:assert/strict` 静态声明的 value binding；type-only import、未绑定名称、源码中可静态识别的遮蔽或重赋值，以及被直接替换的 namespace 方法不会被识别。比较断言和单参数 `assert()` / `assert.ok()` 会参与现有规则；不会追踪任意封装。
- matcher 识别接受从 `@jest/globals`、`vitest` 和 `@playwright/test` 导入的具名 `expect`，也支持通过 `@jest/globals`、`vitest` 或 `@playwright/test` 的字面量 CommonJS 解构取得别名。源码中可见的词法遮蔽或被重新赋值的 CommonJS 别名不会计入；文件级本地 `expect` 会抑制隐式全局 matcher 名称。
- matcher 链支持 `.not`、`.resolves` 和 `.rejects`。Vitest 与 Playwright 的 `expect.soft`、`expect.poll` 调用也会识别；只有表达式体或单一直接 `return` 的 polling 回调会被解开。取反的 API 请求回显/空结果和 E2E 空 UI 检查不会命中对应弱规则；取反、promise modifier 和非字面量 polling 结果不会触发字面量比较类 `FAKE` 规则。
- `E2E008` 会识别直接表达式语句中的异步 Playwright matcher，以及被 `void` 明确丢弃的 matcher。已 `await` 的 matcher、同步 matcher，以及直接传入 `Promise.all` 的 matcher都不会触发该规则。
- 测试注册接受未被遮蔽的全局 `test`/`it` 名称，以及从受支持框架模块导入的别名和各框架支持的 `.skip`、`.only`、`.concurrent`、`.failing` / `.fails`、Playwright `.fail` / `.fixme`、`.each`、`.skipIf`、`.runIf` 形式。回调参数可以引用同文件的函数声明或直接初始化为函数的变量；不会跟踪导入回调、任意别名、被遮蔽的绑定或存在静态写入的绑定，也不会通过本地 test wrapper 推断回调。
- 含插值的测试和 suite 名称按源码形式保留；每个注册调用点只提取一次，不求值循环表达式。
- 规则遍历会跳过未调用的嵌套函数；仅跟踪静态可达、同作用域且调用前没有可见绑定写入的本地 helper 链。Promise callback 仅在 primitive `Promise.resolve` / `Promise.reject` 链被测试回调返回或 await 时计入；当已知 settlement 使选中的 callback 不会执行、handler 被省略、返回基本字面量，或 `finally` handler 结果为空时，都会保留已知状态。另识别受支持 Vitest/Playwright `expect` binding 的 `expect.poll` callback、Playwright `expect(callback).toPass()` callback，以及直接 Array 字面量上能静态保证至少迭代一次的部分方法。`reduce` / `reduceRight` 必须能从字面量元素和可选初始值证明会迭代。断言若只位于接收者不透明的 Array callback 中，会将 UT001/E2E001 降为 WEAK；不会据此认定 callback 一定执行。只有从 `fast-check` 导入的默认或 namespace binding，且调用形式为 `fc.assert(fc.property(..., callback))`，同时 `numRuns` 未提供或是静态正安全整数时，才会跟踪 property callback。Array `sort` / `toSorted`、任意方法和 helper 别名不会被假定为已执行。
- `PARSER001` 仅报告源码语法，不执行、解析依赖或验证运行时类型。
- 未命中的测试刻意保持为 `UNASSESSED`。
- v1.2 规则只使用有边界的源码形式；转换后的值、稳定 selector、重新抛出、已 await 调用、`Promise.all` 和混合有效断言是代表性不可触发样例。
- `ata benchmark` 比对版本化源码 fixture 以及精确的 rule/classification 身份；它是 fixture 一致性证据，不是运行时质量、覆盖率、mutation、precision、recall 或发布证据。

## 仅 FAKE 门禁边界

显式 `ata gate` 是仅 FAKE 门禁：它要求 `mode: "gate"` 与 `blockOn: ["FAKE"]`。WEAK 永不阻断，通过门禁也不证明测试是 STRONG。

`ata decision` 仅将已校验的静态汇总事实投影为 version `1` 建议性决策。它拒绝 semantic/mutation 附件和未知字段；策略/基线 ID 仅为上下文。有效决策返回 `0`，但它不是 CI 门禁、豁免、发布决定，也不能证明未标记测试是 `STRONG`。

v0.9 的 GitHub Actions 参考工作流从 PR base SHA 或手动 `base-ref` 选择变更的受支持测试文件，仅将允许字段投影到 `ata decision`，并把静态审计结果写入 Job Summary。发现项是建议性结果，不会让该工作流失败；无效输入仍以退出码 `2` 失败。它不创建 PR 评论。

可选的 `--policy` 文件是这项纯源码审计的输入。它的 advisory `disabledRuleIds` 只影响策略展示以及禁用/活跃选择计数。它绝不移除发现项，也不改变规则分类、严重性、置信度、静态汇总、FTR、Trust Score 或退出码；策略不是 CI 门禁或发布决定。无效策略输入返回退出码 `2`。

## 新增规则

先写最小失败测试，确认它因缺少的行为而失败，再添加最小 AST 谓词。规则必须有稳定 namespace ID、信息/建议中的证据边界、正向与代表性反向测试；同次改动更新本目录与英文版本。
