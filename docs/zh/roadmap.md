# 迭代计划

## 已交付的 MVP 基础

- 无效 / 虚假信心测试的问题定义。
- 源码 AST 管道、确定性规则、CLI、JSON/文本报告、透明分数/FTR。
- 直接 Jest/Vitest/Playwright 回调支持、基准 fixture、双语 Skill 与 CI 基础。

## 顺序原则

1. 先定义虚假信心模式，再自动化。
2. 区分确定性证据、模型推断和执行证据。
3. 优先准确、可解释，而不是大量规则。
4. 没有稳定的误报证据前，CI Gate 必须是 opt-in。

v0.7 至 v0.9 保持纯源码且建议性，并保留纯源码/建议性边界：它们不执行被审计源码，也不改变发现项的静态含义。v1.0 保持纯源码，并是稳定、显式 opt-in 的质量门禁；仅当仓库策略启用时才阻断。v2.0 的运行时、变异和 LLM 适配器需要独立的设计和证据。可选 AI 辅助仅在 v1.0 之后、且静态优先：默认关闭、仅建议性、绝不输出 `FAKE`/`WEAK`/`STRONG`/`INVALID`，也不改变静态汇总、FTR、Trust Score、退出语义或门禁输入。详见 [`docs/superpowers/specs/2026-09-08-optional-ai-assist-design.md`](../superpowers/specs/2026-09-08-optional-ai-assist-design.md)。

## v0.2 兼容性矩阵

| 框架       | 直接 `test` / `it` | 嵌套套件名称         | `test.each` / `it.each` | 解析诊断 |
| ---------- | ------------------ | -------------------- | ----------------------- | -------- |
| Jest       | 支持               | 支持                 | 支持该语法              | 支持     |
| Vitest     | 支持               | 支持                 | 支持该语法              | 支持     |

`ata.config.json` 可提供测试文件 basename 的 `include` 和 `exclude` 数组。这是有限的源码选择控制，不是框架运行时配置。

## v0.3 语义审计契约

`--semantic-report <path>` 加载 version `1` 的建议性 JSON 产物。默认操作完全离线。`semanticProvider` 配置接受 `offline`、`openai` 或 `anthropic`，以及环境变量名和可选模型；v0.3 只校验配置，绝不读取 Key 或发起网络调用。[`test-quality-audit/evals/semantic-report-v1.json`](../../test-quality-audit/evals/semantic-report-v1.json) 是该契约的版本化接受/拒绝评估语料。

## v0.4 Mutation 证据契约

`--mutation-report <path>` 加载 version `1` 的离线产物，其中包含引擎标识、已记录命令、阈值及来源、变异体总数/杀死数/存活数和推导出的分数。命令仅用于溯源，绝不会被执行。适配器校验数量与分数一致性；低于已记录阈值的分数只是建议，不是门禁，绝不改变静态结果或退出码。

## v0.6.0 建议性策略契约

`--policy <path>` 接受 version `1` 的 JSON 对象：必须有非空 `id`、`mode: "advisory"`，并可选提供唯一且非空的 `disabledRuleIds`。它是纯源码审计的输入，只在输出中增加策略选择计数，不移除发现项，也不改变静态分类、汇总、FTR、Trust Score 或退出码。无效策略输入返回退出码 `2`；不存在默认 CI 门禁或发布决定。

## 不作承诺

日期、覆盖率目标、模型供应商、变异引擎、未来框架与门禁阈值尚未承诺，需要实证和维护者决策。
