# 迭代计划

## 当前基线

v1.0 是当前稳定基线。它以确定性、纯源码方式审计 JavaScript 与 TypeScript 测试，并提供显式 opt-in 的仅 `FAKE` 策略门禁。审计或门禁通过不证明测试很强。

## 已交付演进

| 范围      | 已交付结果                                                       |
| --------- | ---------------------------------------------------------------- |
| v0.1–v0.3 | AST 提取、确定性规则、CLI 报告和离线证据契约。                   |
| v0.4–v0.5 | 变异证据输入、Unit/API/E2E 规则扩展和变更文件选择。              |
| v0.6–v0.9 | 建议性策略、基线、决策投影和最小权限 GitHub Actions 参考工作流。 |
| v1.0      | 显式 opt-in 的仅 `FAKE` 门禁，具有稳定的 `0`/`1`/`2` 失败语义。  |

已完成版本的决策理由见中文[历史文档](../history/product-evolution.md)。

## v2.0：待设计方向

v2.0 尚未交付。只有完成独立设计批准、安全审查和实施证据后，才可能增加显式的运行时、变异和 LLM 适配器。保留的[可选 AI 辅助设计](../superpowers/specs/2026-09-08-optional-ai-assist-design.md)是规划输入，不是交付声明。

未来适配器必须保持可选；不得默认执行被审计源码、隐式读取凭据或未经明确设计和用户控制调用网络。它们不得改变静态 finding/classification、FTR、Trust Score、既有退出语义或显式门禁输入。

## 规划规则

- 本迭代计划是未来版本计划的唯一详细来源；README 和 Context 只能摘要或链接它。
- 优先可解释、纯源码的证据，而不是增加规则数量。
- `FAKE` 必须保持确定性；上下文提示保持 `WEAK` 或省略。
- CI 门禁始终保持显式 opt-in。

## 不作承诺

未获得维护者决策和验证证据前，不承诺日期、供应商、变异引擎、阈值、覆盖率目标、未来框架支持或兼容性保证。
