# Allure 3 风格静态审计 HTML 报告设计

## 目标

将 `ata review --format html` 的单页报告改造为“静态审计工作台”。参考 Allure 3 Awesome 报告的概览、分类与逐层定位体验，但保持 AI Test Auditor 的纯源码、离线、单文件边界。

## 不变边界

- 不执行、导入或评估被审计源码；不读取凭据；不调用网络。
- 不引入测试执行状态、耗时、重试、flaky、历史趋势、覆盖率或运行时通过率。
- 不改变 JSON schema、静态 finding、classification、FTR、Trust Score 或 `0`/`1`/`2` 退出语义。
- 单个 HTML 文件内嵌样式和脚本，不使用 CDN、外部字体、图片或框架运行时。
- `UNASSESSED` 继续表示未被现有规则覆盖，绝不呈现为通过或强测试。

## 信息架构

页面按“范围说明 → 风险概览 → 分类导航 → 发现定位”组织：

1. 顶部保留静态审计边界，并显示生成报告时已有的语言。
2. 概览区显示静态审计项、已识别测试回调、FAKE、WEAK、INVALID、UNASSESSED、FTR 与 Trust Score；测试执行数不出现。
3. 左侧导航（窄屏改为顶部横向区域）提供分类、规则 ID 和文件聚合入口，每项显示计数。
4. 主区域按当前筛选展示发现卡片；卡片按文件分组，显示中文分类/严重度、稳定规则 ID、行号、消息与 remediation。
5. 规则 ID 保留悬浮说明；`E2E001`–`E2E004` 至少提供中英文简短规则定义。

## 交互

- 分类、规则和文件导航与已有下拉/文本筛选共用同一前端筛选状态，避免浏览器端重新审计。
- 支持“清除筛选”和当前结果为空状态；筛选仅隐藏或展示既有 finding。
- 发现卡片可折叠显示 remediation，默认保持关键信息可见，避免长报告首屏噪声。
- 所有控制元素具有可见文本、键盘可聚焦状态和原生 title/语义标签；不依赖颜色传递分类。

## 数据与实现边界

`renderHtml(result, locale)` 仍只接收既有 `AuditResult`。展示层可从 `result.findings` 计算分类、规则和文件计数，但不得修改或序列化完整测试源码。HTML 不新增外部输入、持久化状态或远程资源。

样式与无依赖脚本继续内嵌在生成结果中。实现可将本地化标签、规则说明与展示聚合提取为 `reporters.ts` 内的受测纯函数；不创建插件系统，也不模仿 Allure 3 的执行、watch 或历史能力。

## 验收与验证

- 中英文 HTML 均显示静态范围、准确的审计项/测试回调口径、分类与严重度标签。
- 有 finding 的样例能通过分类、规则与文件导航缩小结果，并能清除筛选恢复全部结果。
- `E2E001`–`E2E004` 悬浮说明存在；规则 ID、classification 与 severity 稳定不变。
- HTML 不包含 `TestCase.source` 或 `TestCase.body`，不含外部 URL、CDN 或网络依赖。
- TDD：先为聚合、导航标记、可折叠卡片与中英文文本添加失败测试，再最小实现。
- 完整验证遵循项目命令：`npm test`、`npm run lint`、`npm run typecheck`、`npm run format:check`、`npm run build`、基准 JSON 审计与 `git diff --check`；既有无关工作树造成的检查干扰单独报告。

## 明确排除

- 不接入 Allure 3 软件包、插件 API 或其结果格式。
- 不呈现测试通过率、失败率、耗时、趋势、环境、owner、标签、步骤或附件。
- 不在本迭代添加辅助函数断言追踪、规则抑制、基线语义或静态规则。
