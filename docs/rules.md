# Rule Catalog

The catalog contains 31 stable rule IDs: 10 Unit, 10 API, 10 E2E, and 1 parser rule.

## Reading a finding

Rule findings are local syntactic evidence with confidence matched to the pattern. A message explains the observed pattern; it does not prove the whole test or application is defective. Use the remediation as a review starting point.

## False-positive controls

- Rules inspect extracted test callbacks and bounded, statically reachable code only; they never inspect execution results.
- `API001` and `E2E002` require the limited matcher to be the sole recognized assertion target.
- `E2E004` fires only for a literal numeric delay; variables are not flagged.
- `UT004`, `API002`, and `E2E003` require every recognized assertion to use the narrow existence/visibility pattern. `.not`, bare expects, and mixed assertions suppress the hint; `.resolves`, `.rejects`, and a statically unwrapped `expect.poll` retain the underlying matcher meaning.
- Node `node:test` assertion recognition requires a statically declared value binding from `node:assert` or `node:assert/strict`; type-only imports, unbound names, statically shadowed or reassigned bindings, and directly replaced namespace methods are not recognized. Comparison assertions and single-argument `assert()` / `assert.ok()` participate in the existing rules; arbitrary wrappers are not followed.
- Matcher recognition accepts named `expect` imports from `@jest/globals`, `vitest`, and `@playwright/test`, plus literal CommonJS destructuring aliases from `@jest/globals`, `vitest`, or `@playwright/test`. A visible lexical shadow or reassigned CommonJS alias is not counted; a top-level local `expect` also suppresses the implicit global matcher name.
- Matcher chains support `.not`, `.resolves`, and `.rejects`. Vitest and Playwright `expect.soft` and `expect.poll` calls are recognized; polling callbacks are unwrapped only when they have an expression body or a single direct `return`. Negated API request-echo/empty-result and empty-UI checks do not match their corresponding weak rules. Literal-comparison FAKE rules do not run for negated, promise-modified, or non-literal polling results.
- `E2E008` recognizes a direct expression statement or an explicit `void` discard of a recognized asynchronous Playwright matcher. Awaited matchers, synchronous matchers, and matchers passed directly to `Promise.all` are not flagged.
- Test registration accepts unshadowed global `test`/`it` names and recognized imports from supported framework modules, including framework-specific `.skip`, `.only`, `.concurrent`, `.failing` / `.fails`, Playwright `.fail` / `.fixme`, `.each`, `.skipIf`, and `.runIf` forms. Callback arguments may reference same-file function declarations or variables initialized directly with a function. Imported callbacks, arbitrary aliases, shadowed bindings, and bindings with statically visible writes are not followed; local test wrappers are not inferred.
- Rule traversal skips uncalled nested functions and follows statically reachable same-scope local helper chains only when calls precede visible binding writes. It follows Promise callbacks only for primitive `Promise.resolve` / `Promise.reject` chains returned from the test callback or awaited; intermediate handlers preserve a known settlement when the selected callback cannot run for that settlement, is omitted, returns a primitive literal, or is an empty `finally` handler. It also follows `expect.poll` callbacks for recognized Vitest/Playwright `expect` bindings, Playwright `expect(callback).toPass()` callbacks, and selected callbacks on direct Array literals with a guaranteed iteration. For `reduce` / `reduceRight`, an iteration must be guaranteed by the literal elements and optional initial value. Array `sort` / `toSorted`, callbacks on opaque receivers, arbitrary methods, and helper aliases are not assumed to execute.
- `PARSER001` reports source syntax only; it does not execute, resolve, or type-check the test at runtime.
- Unflagged tests are deliberately `UNASSESSED`.
- The v1.2 rules use bounded source forms; transformed values, stable selectors, rethrows, awaited calls, `Promise.all`, and mixed meaningful assertions are representative non-triggers.
- `ata benchmark` compares versioned source fixtures and exact finding/classification identities; it is fixture conformance evidence, not runtime quality, coverage, mutation, precision, recall, or release evidence.

## FAKE-only gate boundary

The explicit `ata gate` command is a FAKE-only gate: it requires `mode: "gate"` and `blockOn: ["FAKE"]`. WEAK never blocks, and a passed gate does not prove a test is STRONG.

`ata decision` projects only validated static summary facts into a version `1` advisory decision. It rejects semantic/mutation attachments and unknown fields; policy/baseline IDs are context only. A valid decision returns `0`, but it is not a CI gate, waiver, release decision, or proof that unflagged tests are `STRONG`.

The v0.9 GitHub Actions reference workflow selects changed supported test files from a PR base SHA or manual `base-ref`, projects only allowed fields into `ata decision`, and keeps the static audit result in the Job Summary. Findings are advisory and do not fail this workflow; malformed input still fails with exit `2`. It creates no PR comments.

An optional `--policy` file is an input to this source-only audit. Its advisory `disabledRuleIds` affect only policy presentation and disabled/active selection counts. They never remove a finding or change a rule classification, severity, confidence, static summary, FTR, Trust Score, or exit code; policy is not a CI gate or release decision. Invalid policy input exits `2`.

## Adding a rule

Write a minimal failing test, verify it fails for the missing behavior, then add the smallest AST predicate. Give the rule a stable namespace ID, an explicit evidence boundary in the message/remediation, and both positive and representative negative test cases. Update this catalog and the Chinese translation in the same change.
